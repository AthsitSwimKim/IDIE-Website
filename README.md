# IDIE Website

เว็บไซต์องค์กร **ID Industrial Engineering Co.,Ltd.**
บริษัทวิศวกรรม ตัวแทนจำหน่าย และงานบริการด้านระบบสื่อสารและสัญญาณเตือนภัยสำหรับ
พื้นที่อุตสาหกรรมและพื้นที่อันตราย — ก่อตั้ง 2549 (2006) ที่ระยอง

## Stack

**หน้าเว็บ** — React 19 · TypeScript · Vite · React Router 7 · Tailwind CSS v4
ฟอนต์ **Inter** (ละติน) + **Kanit** (ไทย) self-host ผ่าน `@fontsource`

**หลังบ้าน** — Node · TypeScript · Express 5 · MySQL 8.4 (`mysql2`) · sharp · zod · nodemailer
รันด้วย `tsx` ไม่มีขั้นตอน build เพื่อให้ import type จาก `src/types/content.ts`
แหล่งเดียวกับหน้าเว็บได้โดยไม่ต้องจัดการ rootDir ข้ามโฟลเดอร์

**Tailwind v4 ไม่มีไฟล์ config** — design token ทั้งหมดอยู่ในบล็อก `@theme` ของ
`src/styles/theme.css` และ `cn()` ใน `src/utils/cn.ts` เป็น clsx เปล่า ๆ **ไม่ได้ merge
คลาสที่ชนกันให้** ถ้าส่ง utility ที่ทับกับของเดิมเข้ามาทาง `className` ผลลัพธ์ขึ้นกับลำดับ
ใน stylesheet ซึ่งเดายาก — ให้กลับไปแก้ที่ variant ของคอมโพเนนต์แทน หรือใช้ `!`

### Framer Motion / Three.js — ถอดออกแล้ว ไม่ต้องทำใหม่

เคยทำ Phase 5 (3D & Motion) จนเสร็จแล้ว **เจ้าของเว็บสั่งรื้อออกทั้งเฟส** เพราะไม่เข้ากับ
ภาพรวมของเว็บ ตอนนี้ไม่มี `framer-motion`, `three` หรือ `@react-three/fiber` ใน
`package.json` และ **ห้ามเริ่มทำใหม่เองโดยไม่ได้สั่ง**

`src/components/ui/Reveal.tsx` ที่เหลืออยู่เป็น wrapper เปล่าที่ยังไม่มี motion จริง —
ตั้งใจให้เป็นจุดเดียวที่จะเติม animation ได้ในอนาคตโดยไม่ต้องไล่แก้ทุก section

### Data layer — จุดสำคัญที่สุดของโปรเจกต์นี้

**Component ห้าม import จากไฟล์ใน `src/data/` โดยตรง** ให้เรียกผ่าน accessor ใน `src/data/index.ts`
เท่านั้น:

```ts
import { getServices, getReferenceCompanies } from '@/data'
```

accessor ทุกตัวเป็น `async` ตั้งแต่วันแรกทั้งที่ข้อมูลยังอยู่ในหน่วยความจำ
เพื่อว่าวันที่ต่อ API หรือ CMS จริงจะ**แก้แค่ `src/data/index.ts` ไฟล์เดียว**
โดยที่ component ไม่ต้องแก้เลย — ซึ่งเกิดขึ้นจริงแล้วตอนต่อระบบหลังบ้าน

อ่านข้อมูลใน component ผ่าน `useAsyncData`:

```tsx
const { data: services } = useAsyncData(getServices)
```

### ข้อมูลจริง vs placeholder

ข้อมูลบริษัท บริการ อุตสาหกรรม แบรนด์ หมวดสินค้า ลูกค้าอ้างอิง ตำแหน่งงาน
**สินค้า 191 รุ่น** และ**เอกสารข้อมูลสินค้า 279 ฉบับ** เป็น**ข้อมูลจริง**

| แบรนด์ | สินค้า | เอกสาร (datasheet) |
|---|---|---|
| Industronic | 82 | 169 |
| MEDC | 62 | 63 |
| FHF | 47 | 47 |

- ข้อมูลบริษัทและลูกค้า — จากเว็บไซต์ปัจจุบันของบริษัท
- สินค้าและเอกสาร — จาก catalog และเว็บไซต์ผู้ผลิต ดึงด้วยสคริปต์ใน `scripts/`

**ไฟล์ที่ลงท้ายด้วย `.generated.ts` ห้ามแก้ด้วยมือ** — จะถูกเขียนทับเมื่อรันสคริปต์ใหม่
ถ้าต้องแก้ข้อความให้แก้ที่สคริปต์หรือที่ไฟล์เขียนมือแทน

คำบรรยายสินค้าทั้งหมดเขียนขึ้นใหม่จากค่าทางเทคนิค ไม่ได้คัดลอกข้อความโฆษณาจาก catalog

ส่วนที่ยังไม่มีข้อมูลจริง (สถิติบางตัว ลูกค้าบางราย) ถูกทำเครื่องหมาย
`_placeholder: true` พร้อมคอมเมนต์ `// TODO: confirm with IDIE` แล้ว**กรองออกจากหน้าเว็บ**
ไม่ใช่แสดงเป็นช่องว่าง:

```bash
grep -rn "_placeholder: true" src/data
```

> บล็อก `PendingContent` ที่เคยประกาศว่า "รอข้อมูลจากบริษัท" บนหน้าเว็บ **ถูกถอดออกทั้งกลไก
> แล้ว (ก.ย. 2026)** ตามที่เจ้าของเว็บสั่ง — หน้าที่ประกาศว่าตัวเองยังไม่เสร็จให้ลูกค้าเห็น
> มีราคาแพงกว่าหน้าที่สั้นแต่ครบ ถ้าได้ข้อมูลมาให้เพิ่มเป็น section ที่มีเนื้อหาจริงไปเลย

รายการที่ต้องขอจากลูกค้าทั้งหมดอยู่ใน [`docs/data-requests.md`](docs/data-requests.md)

### การตัดบรรทัดของสองภาษาไม่เหมือนกัน

**ไทย** — ไม่มีช่องว่างระหว่างคำ เบราว์เซอร์ตัดด้วยพจนานุกรมในตัวซึ่ง CSS สั่งไม่ได้
`src/components/ui/KeepPhrases.tsx` เก็บรายการวลีที่ห้ามตัดกลาง (เช่น "สัญญาณเตือนภัย",
"พื้นที่อันตราย") แล้วครอบด้วย `whitespace-nowrap` ให้ทีละก้อน

> **เกณฑ์การเพิ่มวลี** — ต้องเป็นวลีที่แยกแล้วเสียความหมาย ไม่ใช่แค่คำยาว และต้องสั้นพอ
> ที่จะไม่กว้างเกินกล่องที่แคบที่สุดที่มันไปปรากฏ เพราะ `whitespace-nowrap` ที่ยาวเกินกล่อง
> จะ**ล้นออกนอกกรอบ**แทนที่จะตัด — รายการนี้ใช้ร่วมกัน 10 หน้า วัดก่อนเพิ่มเสมอ

**อังกฤษ** — ตัดที่ช่องว่าง จึงใช้ CSS จัดการได้ `theme.css` ตั้ง `text-wrap: pretty`
ให้ย่อหน้าและ `text-wrap: balance` ให้หัวข้อ **เฉพาะ `:lang(en)`** (เคยวัดแล้วว่า `balance`
ทำให้พาดหัวไทยแย่ลง) ส่วนคำที่มีขีดกลางซึ่งห้ามขาดครึ่ง เช่น `explosion‑proof`,
`after‑sales`, `plant‑wide` ใช้ **ขีดที่ห้ามตัด (U+2011)** ในข้อความต้นทาง

## ขอบเขต

เดิมโครงการนี้เป็น **frontend เท่านั้น** — ส.ค. 2026 ลูกค้าขอเพิ่มระบบหลังบ้าน
สำหรับลงข่าวสาร ผลงาน และลูกค้าอ้างอิงเอง จึงมีเซิร์ฟเวอร์ Node + MySQL เพิ่มเข้ามาใน `server/`

**ยังไม่มี** e-commerce, ระบบสมาชิกสำหรับผู้เข้าชม หรือ CMS สำหรับเนื้อหาส่วนอื่น

รายละเอียดขอบเขต บทบาทในทีม และ spec รายหน้าอยู่ใน Claude Skill ของโปรเจกต์:
`.claude/skills/idie-website/`

## ระบบหลังบ้าน (`server/`)

ทีมงาน IDIE จัดการเนื้อหาเองได้ที่ `/admin` — **ข่าวสาร · ผลงาน · ลูกค้าอ้างอิง · บัญชีผู้ใช้**
เก็บใน **MySQL** ส่วนรูปเก็บเป็นไฟล์บนดิสก์ (`server/uploads/`) แล้วฐานข้อมูลเก็บแค่ที่อยู่ไฟล์
หน้าแดชบอร์ดแสดงจำนวนผู้เข้าชมเว็บ ซึ่งนับจริงที่ `POST /api/visitors`

เนื้อหาที่เหลือทั้งหมด (บริษัท บริการ สินค้า แบรนด์) **ยังอยู่ใน `src/data/` เหมือนเดิม**
เพราะเปลี่ยนแทบไม่ได้และไม่ควรแก้ผ่านหน้าเว็บโดยไม่ผ่านการรีวิว

แบบฟอร์มติดต่อ**ส่งอีเมลจริงแล้ว** ผ่าน nodemailer ถ้าไม่ได้ตั้งค่า SMTP ครบ
(`SMTP_HOST` · `SMTP_USER` · `MAIL_TO`) ระบบจะบันทึกคำขอลงฐานข้อมูลอย่างเดียวโดยไม่ส่งเมล
และไม่ทำให้ฟอร์มพัง

วิธีติดตั้ง ตั้งค่า และขึ้น production อยู่ใน [`server/README.md`](server/README.md)

> ถ้า API ล่ม หน้าเว็บสาธารณะ**ไม่พัง** — `getNews`/`getProjects` กลืน error
> เป็นค่าว่าง หน้า News/Projects จึงแสดง empty state ที่ออกแบบไว้ตามเดิม
> และเขียนสาเหตุจริงลง console ให้คนที่มาไล่ปัญหาเห็น

### Docker — 2 คอนเทนเนอร์

| คอนเทนเนอร์ | image | หน้าที่ | พอร์ต |
|---|---|---|---|
| `idie-mysql` | `mysql:8.4` | ฐานข้อมูล | 3307 → 3306 |
| `idie-api` | build จาก `server/Dockerfile` | API หลังบ้าน | 3001 → 3001 |

```bash
docker compose --env-file server/.env up -d
```

**ต้องมี `--env-file server/.env` ทุกครั้ง** — ไม่มีรหัสผ่านอยู่ใน `docker-compose.yml`
ทั้งสองตัวตั้ง `restart: unless-stopped` เปิด Docker Desktop แล้วขึ้นเองทั้งคู่
และ `api` รอจนกว่า `db` จะผ่าน health check จริงก่อนเริ่ม

ฝั่งหน้าเว็บ**ไม่ได้อยู่ใน Docker** รันด้วย `npm run dev` เพราะต้องการ hot reload
และ Vite ส่งต่อ `/api` ไปที่พอร์ต 3001 อยู่แล้ว

### ✅ font preload ใช้งานแล้ว

plugin `idie:preload-critical-fonts` ใน `vite.config.ts` มีไว้ใส่ `<link rel="preload">`
ให้ฟอนต์หลักตอน build เพราะ `@fontsource` ตั้ง `font-display: swap` ให้ทุกไฟล์ —
ถ้าไม่ preload เบราว์เซอร์วาดด้วยฟอนต์ระบบก่อนแล้วค่อยสลับ วัดจริงแล้วบล็อก hero
สูงต่างกันถึง 76px ทั้งหน้าจึงกระโดดหนึ่งครั้ง (เคยวัดได้ CLS 0.113 เกินงบ)

`CRITICAL_FONT_PATTERN` จับเฉพาะ **Inter latin** และ **Kanit thai** อย่างละ 4 น้ำหนัก
รวม 8 ไฟล์ โดยไม่ preload subset ภาษาอื่นที่หน้าเว็บไม่ได้ใช้ ตรวจผลหลัง build ได้ด้วย:

```bash
npm run build && grep -c 'rel="preload"' dist/index.html
```

ผลจาก production build วันที่ 10 ก.ย. 2026 ได้ preload **8 รายการ** ตามที่ตั้งใจ
หากเปลี่ยนตระกูลฟอนต์ น้ำหนัก หรือ subset ในอนาคต ต้องแก้ pattern นี้ตามด้วย

วัด CLS ซ้ำวันที่ 10 ก.ย. 2026 บน `idie-preview-cold` พอร์ต 4176 โดยปิด cache และจำลอง
เครือข่าย 3G ครบ 10 กรณี (TH/EN × 5 viewport) — ค่าสูงสุด **0.025** ที่หน้าอังกฤษ
ขนาด 1024×768 และทดสอบกรณีนี้ซ้ำอีก 3 รอบได้ 0.025 / 0 / 0.025 ผ่านงบ ≤ 0.1

### เมนูเดสก์ท็อปเริ่มที่ `xl` (1280) ไม่ใช่ `lg` (1024)

เมนู 8 รายการภาษาไทยกว้าง 698px รวมกับโลโก้และปุ่มสลับภาษาแล้วต้องการ ~1012px
แต่ที่ 1024 มีที่ว่างจริงแค่ 913px ทำให้โลโก้ถูกบีบจนตัวอักษรเรียงลงมาทีละตัว
ช่วง 1024–1279 จึงใช้เมนูแบบมือถือแทน ถ้าจะย้ายกลับไป `lg` ต้องลดจำนวนเมนูหรือย่อข้อความก่อน

ท้ายเว็บก็ใช้หลักเดียวกัน — เรียงสี่คอลัมน์ตั้งแต่ `xl` เพราะที่ 1024 ของที่ต้องใส่
(ตราบริษัท 278px + ที่อยู่ 407px + ลิงก์ 198px + ช่องไฟ) รวม 1,003px แต่มีที่จริง 913px
